Technical Guide - Distributed Cluster

This guide expands on the project overview from the main Pages landing page and presents the same architecture, workflow, and diagram style in a documentation-focused format.

Overview

This distributed compute experiment launches workers over SSH and exchanges deterministic matrix chunks over a trusted LAN or WireGuard network. Every application message uses an explicit length-prefixed JSON frame, and the final result is checked against locally recomputed ground truth.

Step 1 - Establish Private Node Connectivity

All nodes must be reachable on a common private network.

  • Use LAN addressing when workers are on the same local network as the orchestrator (IPv4 families 192.*, 10.*, or 172.*).
  • Use WireGuard for workers outside the host's local network.
  • Validate connectivity with ping and ssh before starting distributed jobs.

Step 2 - Bash Orchestrator (Master Control)

The host script starts worker processes remotely over SSH and launches rank 0 locally.

#!/usr/bin/env bash
set -euo pipefail

# The project scripts perform health checks, choose LAN/WireGuard routes,
# start every worker rank, and launch rank 0 locally.
bash deploy_cluster.sh
bash run_cluster.sh

# Optional reproducibility controls:
MATRIX_SIZE=600 MATRIX_SEED=20260726 bash run_cluster.sh

SSH Notes

  • Use key-based authentication only.
  • Restrict SSH exposure to trusted private interfaces (LAN and/or VPN).
  • Prefer non-root users with minimal privileges.

Step 3 - Worker Script (train_dist.py)

Rank 0 builds deterministic matrix A, partitions its rows, and sends every worker a framed JSON request. Each worker independently derives the same deterministic matrix B, computes its assigned rows, and returns a framed result plus measured compute time. 

# Shared by workers and the verifier:
A[row, col] = ((row * 17 + col * 31 + seed) % 1000) / 1000
B[row, col] = ((row * 29 + col * 13 + seed + 97) % 1000) / 1000

# Network payloads are JSON data preceded by an unsigned 8-byte length.
send_frame(socket, encode_json(message))
message = json.loads(receive_frame(socket).decode("utf-8"))

Known Constraints and Risks

1) Network Bottleneck

  • Device-local memory bandwidth is much higher than Internet links.
  • Transferring JSON matrix chunks can become communication-bound quickly.

2) iOS Background Execution Limits

  • iOS may suspend or terminate long-running background terminal processes.
  • Keep apps active and device power settings in mind during experiments.

3) Reliability

  • WAN jitter and packet loss can create stragglers and unstable step times.
  • Add retries, health checks, and timeout handling in orchestration scripts.

Automated Summary Report Generator (generate_report.py)

Use a reporting script to compile telemetry into a final Markdown report.

Purpose

  • Parse cluster_performance.csv.
  • Compute speedup metrics.
  • Emit FINAL_PROJECT_SUMMARY.md.

Implemented Data-Quality Safeguards

  • Rank 0 writes actual transfer, compute, and wall-clock measurements to run_metrics.json.
  • The logger validates the metrics schema and refuses negative or incomplete measurements.
  • Speedup is calculated only when a measured one-node baseline exists.
  • The verifier records pass/fail status and numerical error statistics.
  • Every pipeline stage returns a nonzero exit code when validation fails.

Pipeline Hook Example (run_cluster.sh)

Append post-run hooks:

# 4) Invoke logger and report generator
if [ -f "./log_metrics.py" ]; then
  python3 ./log_metrics.py run_metrics.json
fi

if [ -f "./generate_report.py" ]; then
  python3 ./generate_report.py
fi
