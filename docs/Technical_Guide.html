Technical Guide - Distributed Cluster

This guide expands on the project overview from the main Pages landing page and presents the same architecture, workflow, and diagram style in a documentation-focused format.

Overview

This distributed compute experiment coordinates multiple devices over a secure network. Instead of transferring raw VRAM contents across devices, the practical approach is to split model or workload state across nodes and synchronize intermediate results.

Step 1 - Establish Private Node Connectivity

All nodes must be reachable on a common private network.

  • Use LAN addressing when workers are on the same local network as the orchestrator (IPv4 families 192.*, 10.*, or 172.*).
  • Use a secure WireGuard mesh for workers outside the host's local network.
  • Validate connectivity with ping and ssh before starting distributed jobs.

Step 2 - Bash Orchestrator (Master Control)

The host script starts worker processes remotely over SSH and launches rank 0 locally.

#!/usr/bin/env bash
set -euo pipefail

# Space-separated SSH aliases. MASTER_IP is optional when auto-detection works.
export WORKER_NODES="worker1 worker2"
export MASTER_IP="192.168.1.33"
export MATRIX_SIZE=600

bash deploy_cluster.sh
bash run_cluster.sh

SSH Notes

  • Use key-based authentication only.
  • Restrict SSH exposure to trusted private interfaces (LAN and/or VPN).
  • Prefer non-root users with minimal privileges.

Step 3 - Worker Script (train_dist.py)

Rank 0 listens on TCP, validates unique worker ranks, assigns contiguous row ranges, and reassembles results. Workers connect with bounded retries, multiply their assigned rows by a deterministic matrix, and return the result using length-prefixed, non-pickle NumPy messages. 

MASTER_ADDR = os.getenv("MASTER_ADDR", "127.0.0.1")
WORLD_SIZE = int(os.getenv("WORLD_SIZE", "1"))
RANK = int(os.getenv("RANK", "0"))
MATRIX_SIZE = int(os.getenv("MATRIX_SIZE", "600"))

if RANK == 0:
    run_master()
else:
    run_worker()

Known Constraints and Risks

1) Network Bottleneck

  • Device-local memory bandwidth is much higher than Internet links.
  • Matrix transfers and worker stragglers can become communication-bound quickly.

2) iOS Background Execution Limits

  • iOS may suspend or terminate long-running background terminal processes.
  • Keep apps active and device power settings in mind during experiments.

3) Reliability

  • WAN jitter and packet loss can create stragglers and unstable step times.
  • Add retries, health checks, and timeout handling in orchestration scripts.
