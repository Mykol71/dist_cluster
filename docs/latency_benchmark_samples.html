Latency Benchmark Guide

src/ping_test.py runs three ICMP probes, parses average round-trip time, and emits one receive-buffer recommendation for run_cluster.sh.

Understanding ping output

PING 10.42.0.2 (workerA) 56 bytes of data — 3 packets
rtt min/avg/max/mdev = 18.42/32.17/71.83/14.55 ms

PING 10.42.0.3 (workerB) 56 bytes of data — 3 packets
rtt min/avg/max/mdev = 22.10/45.63/118.24/27.38 ms
FieldMeaning
minBest observed round-trip time.
avgAverage round-trip time used for the recommendation.
maxWorst observed spike; large values indicate jitter.
mdevMean deviation; higher values indicate a less stable route.

Script output

The script prints exactly one of these values:

262144    # average latency below 30 ms
1048576   # average latency from 30 ms through 99.999 ms
2097152   # average latency at least 100 ms, or probe failure

The orchestrator probes every worker and uses the largest recommendation so the slowest active route determines the receive size.

Decision table

Average latencyReceive sizeInterpretation
< 30 ms256 KBHealthy local or low-contention path.
30–99 ms1 MBModerate latency; amortize receive overhead.
≥ 100 ms2 MBHigh latency; expect network-bound execution.
Probe failure2 MBConservative fallback; check reachability before running.

Healthy path

rtt min/avg/max/mdev = 12.00/20.00/35.00/8.00 ms

The script selects 256 KB. Small receive calls keep framed messages responsive.

Moderate degradation

rtt min/avg/max/mdev = 20.00/55.00/120.00/30.00 ms

The script selects 1 MB. Expect communication overhead to become more visible.

Severe degradation

rtt min/avg/max/mdev = 80.00/180.00/450.00/95.00 ms

The script selects 2 MB. Investigate packet loss and consider moving the worker to a better route before a large run.

Run manually

# Profile one worker
python3 ./src/ping_test.py workerA

# Profile all configured workers
for node in workerA workerB; do
  printf '%s: ' "$node"
  python3 ./src/ping_test.py "$node"
done
