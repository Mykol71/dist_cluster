SSH Hardening Guide

Apply these controls to the master and every worker before running cluster experiments over a WireGuard mesh.

Safety: Keep a second terminal or console recovery path open while changing SSH configuration. Confirm a fresh connection works before closing the existing session.

1. Use key-based authentication

Generate a dedicated ED25519 key on the orchestrator:

ssh-keygen -t ed25519 -C "dist_cluster_orchestrator" \
  -f ~/.ssh/dist_cluster_id

Install its public key on each worker and verify login:

ssh-copy-id -i ~/.ssh/dist_cluster_id.pub mobile@10.42.0.2
ssh-copy-id -i ~/.ssh/dist_cluster_id.pub mobile@10.42.0.3

ssh -i ~/.ssh/dist_cluster_id mobile@10.42.0.2 \
  echo "key login OK"

2. Disable password and root login

Edit /etc/ssh/sshd_config on every worker:

PasswordAuthentication no
ChallengeResponseAuthentication no
UsePAM no
PermitRootLogin no

Reload the SSH daemon after saving:

# Linux / Alpine (iSH)
service sshd restart

# systemd-based Linux
sudo systemctl reload sshd

3. Restrict SSH to WireGuard

Bind SSH to the node's private WireGuard address:

ListenAddress 10.42.0.2

Or constrain the allowed user and client subnet:

AllowUsers mobile@10.42.0.*

4. Use a least-privilege account

adduser --disabled-password --gecos "" mobile
chown -R mobile:mobile /app

Then explicitly allow that user and deny root:

PermitRootLogin no
AllowUsers mobile

5. Add rate limiting

On supported Linux workers, install and enable fail2ban:

# Debian / Ubuntu
sudo apt-get install -y fail2ban

# Alpine / iSH
apk add fail2ban

Create /etc/fail2ban/jail.local:

[sshd]
enabled  = true
port     = ssh
maxretry = 5
bantime  = 600
findtime = 120
sudo systemctl enable --now fail2ban

Where fail2ban is unavailable, apply an equivalent firewall rate limit:

iptables -A INPUT -p tcp --dport 22 -m state --state NEW \
  -m recent --set --name SSH
iptables -A INPUT -p tcp --dport 22 -m state --state NEW \
  -m recent --update --seconds 60 --hitcount 5 --name SSH -j DROP

6. Allow-list the WireGuard subnet

iptables -A INPUT -p tcp --dport 22 \
  -s 10.42.0.0/24 -j ACCEPT
iptables -A INPUT -p tcp --dport 22 -j DROP

Persist the firewall policy across reboots:

# Debian / Ubuntu
sudo apt-get install -y iptables-persistent
sudo netfilter-persistent save

# Alpine / iSH
/etc/init.d/iptables save

7. Enable useful audit logs

Set LogLevel VERBOSE in sshd_config, then review logs:

# systemd journal
journalctl -u sshd --since "1 hour ago"

# Traditional syslog
tail -n 50 /var/log/auth.log

Checklist

  • Dedicated ED25519 key deployed to every worker
  • Password authentication disabled
  • Root login disabled
  • SSH restricted to the WireGuard address or subnet
  • Dedicated non-root cluster user configured
  • Rate limiting enabled
  • Firewall policy persisted
  • Verbose SSH logging enabled and reviewed
